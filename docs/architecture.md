# Architecture

GPUI owns application/window lifetime, layout, input dispatch and presentation. Each viewport has a worker that owns a Nightshade `WgpuRenderer`, `SingleViewHost`, GPU ring and scene. GPU objects are constructed on that worker; `RenderHooks` are not assumed Send. The host composes render inputs with the real `compose_single_view` API, executes `render_frame`, then calls `restore_single_view`, including on returned render errors.

The cube host registers the actual Shading, Geometry and Outline plugins. Shader publication precedes graph configuration; presentation passes are installed after geometry. The first render materializes the graph before layout-driven resizing. This avoids a reproduced blank frame when a fresh graph is resized before its first execution. This is an explicit initialization render, not a hidden window. The host reserves entity zero because the upstream outline shader treats zero as background.

`App::into_schedules` is not a complete application runner: it checks plugin requirements, orders stages and returns world/startup/stages, dropping other App fields. Nightshade's `commands::into_parts` extracts render hooks before converting the app. The current integration uses that path for shader/graph hooks, and `SingleViewHost` for rendering. The full viewer uses `ViewerRuntime` instead: it retains plugin-owned guards before `into_parts`, initializes offscreen, and runs timing, stages, renderer update, preparation and render on each worker tick. The original glTF, animation and agent systems operate on that world. `ViewerCorePlugin` excludes the retained UI runtime; native UI remains an optional composition.

## Frame and resource ownership

The control mailbox holds the newest camera/size request alongside a bounded ordered pointer queue. CPU presentation holds at most three staging buffers and one unpublished completed image. GPUI holds the current image and frame scene references. Replacing an image calls `Window::drop_image`; entity release calls `App::drop_image`. External images report one frame so atlas eviction reaches their GPU entries too.

A resize advances a generation. CPU callbacks cannot publish an obsolete generation. A ring is replaced only after its producer work is ready; readback drains mapping callbacks before replacement. Shared images can outlive their ring through owned NT handles and GPUI's imported COM resources. Pixel storage is capped at 256 MiB per presentation ring; Nightshade scene/depth/material/pipeline caches are additional memory, not included in that cap.

The GPU slot lease lasts through the generic image, atlas entry and scene references. Reuse requires all leases to expire plus the consumer fence to complete. Unsampled dropped frames require producer completion only. The worker does not submit more render work when no presentation slot is available. No GPUI UI callback waits for a fence or maps GPU memory.

Workers sleep on a condition variable when idle. UI polling checks for updates at 16 ms intervals but only invalidates when a frame or diagnostic changed. The cube renders on demand. The full viewer requests continuous ticks for loading, animation, camera smoothing and native agent servicing; presentation backpressure still bounds submission. Application quit signals workers and joins them through GPUI's background executor, subject to GPUI's shutdown timeout.

## Input

Canvas prepaint reports logical bounds and scale. Physical dimensions use rounded logical size times scale. Pointer picking subtracts the viewport origin before scaling. Camera orbit/pan/zoom configuration is coalesced. A pick dispatch uses Nightshade's depth/entity-ID compute readback, then selects an entity and enables the existing outline pass. Keyboard focus is assigned on pointer down. The editor reserves left-drag for trunk gizmos and uses right-drag for camera orbit (Shift pans in world X/Y). Window capture-phase listeners deliver drag motion and release across element boundaries; focus loss, Escape and size/DPI changes clear pending input and restore unfinished gizmo transforms. View-plane pan, broader outside-window capture stress, full shortcut coverage and drag-and-drop remain unfinished.

Multiple viewports currently use independent worlds/devices. A shared ECS with multiple camera producers is a separate lifecycle integration and is not claimed here.

The GPUI editor sends existing `ViewerAction` values through a 256-entry bridge to the core queue (capacity 4096). It reads an owned latest snapshot behind an Arc, so no ECS references cross threads. Camera input applies deltas to the current orbit targets to preserve core framing and agent changes.

Asset browsing reuses trunk page queries through owned snapshots and a search action in the original dispatcher. The GPUI thumbnail cache requests only the current page, caps HTTP work at four requests, decodes off-thread, rejects oversized inputs and explicitly evicts images on page changes/entity release. Local preview generation is not delegated to a hidden native viewer.

Animation controls reuse trunk player/layer/morph/skeleton actions. Snapshots copy morph values from the ECS rather than stale import metadata. Dynamic input entities are retained only for the selected mesh and active layers; subscriptions and focus are released when their binding disappears. Scene root/generation and clip checks reject stale frontend weight edits.

The rendering pane uses owned control indices and effective RenderSettings snapshots, dispatching the same settings actions used by the native frontend and agent. Screenshot capture reuses the renderer queue/readback/writer; GLB export reuses trunk scene gathering and serialization. Native dialogs and export operations run on the viewer worker.

Pointer edges are delivered one per rendered tick, so a queued press/release pair cannot collapse into one ECS frame. Consecutive moves coalesce, and overflow resets to cancellation. Scene input uses the existing offscreen injection APIs and core picking/gizmo systems. Camera bindings avoid applying native left-button orbit alongside gizmo input. Frame publication accepts the latest completed image during input rather than invalidating every frame on a new pointer/camera request; CPU resize-generation checks remain in place.

Dock visibility is evaluated from the live pane tree (active tabs, open docks and the zoomed group). The viewport forwards visibility edges to the worker, cancelling queued gestures and waking its condition variable. Hidden workers service the host without presentation; the viewer separates schedule advancement from extraction/rendering and publishes owned snapshots on both paths. Render-command queues and pending screenshot readback can request offscreen frames while hidden. Outstanding readbacks drain, current images/allocations stay bounded, and resizing resumes on the existing host. just test-gpu includes the hidden/resume worker regression.

Each viewport combines container visibility with GPUI's platform-window visibility and forwards only effective presentation edges. The component observes window visibility even while its view is not being drawn, so minimize can suspend immediately and restore can wake the retained worker. The two sources remain independent: a hidden tab stays hidden across a window restore. The pinned Windows backend reports shown/non-minimized state, not coverage by other windows. Readback frame sequences help inspect suspension/resume alongside the GPU regression's exact worker counters.

## Embedding presentation contract

`ViewportFrame` pairs each immutable owned GPUI image with `FrameInfo` across the worker mailbox. CPU metadata comes from the completed readback; shared metadata keeps the producer FrameId alongside the queued shared texture, including when older pending copies are dropped. The view reports metadata only for its retained image. `PresentationStatus` records actual backend/adapter, visibility, initialization/fallback/error separately from the requested preference. Public inspection exposes no native handles or GPU completion claims. The formerly unused generic GPU-frame trait/enum were removed. See [embedding API](integration.md).

Retired external imports are polled on the existing 16 ms viewport task, bound to the GPUI window after first render. The atlas's default polling hook does nothing on other backends. On Windows it drops only completed imports, independently of rendering: otherwise leases can fill the producer pool while the UI waits for the next published frame to schedule a draw. Visibility suspension still stops image production, while retirement polling remains nonblocking.
